UDP Streaming Protocol Architecture

Adaptive Sliding-Window FEC & Prioritized ARQ

1. Core System Design

To overcome loss, reordering, and jitter under a strict 2.0× bandwidth ceiling, the system implements a hybrid Sliding-Window XOR FEC + Prioritized ARQ architecture.

  • Adaptive Window size (W): Configures $W=2$ for low-delay profiles ($\le 60$ms) to prevent deadline misses, and $W=4$ for high-delay profiles to maximize recovery depth.
  • Iterative Back-Substitution: Decoder runs a recursive solver on every packet arrival. If a window has exactly 1 missing packet, it is immediately solved.
  • Network-Level Loss Tracking: Receiver monitors raw network packet drops using a dedicated bitmap before recovery, enabling precise mode estimation at the sender.

2. Priority Bandwidth Clamping

To prevent bandwidth cap violations under severe channel drops, the sender coordinates a priority queue based on real-time loopback bandwidth ratios.

  • Original Data: Always transmitted immediately with zero delay.
  • NACK Retransmissions: High-priority recovery packets. Transmitted only if current ratio is $\le 1.98$.
  • Proactive Duplicates / FEC: Low-priority recovery packets. Dropped if current ratio exceeds $\le 1.90$.
  • Cap Compliance: Eliminates the risk of exceeding the 2.00× overhead cap while ensuring NACK responses are never choked.
